1. Overview

Vayu is a compiled programming language with Python-inspired syntax, static typing, and a native execution path. Source files use the .vyu extension. The Vayu repository owns the language frontend, semantic analysis, intermediate representations, and the lowering step into VCBIR. VCB is a separate C++20 backend that consumes VCBIR and emits x86-64 PE or ELF executables.

Vayu (.vyu)
Backend IR

Frontend stack
Lexer, parser, AST, semantic checker, bytecode VM, native lowering
Backend stack
VCBIR parser, x86-64 codegen, demand-driven runtime, PE/ELF writers

Design goals

Readable syntax, native performance, low-level control when required, static typing with inference, and interoperability with C and CPython.

Repository split

Language semantics and IR lowering live in Vayu. Machine code generation and image writing live in VCB. The contract between them is the .vcbir file format.

2. Architecture

The system is organized as a frontend/backend pipeline. Multiple execution modes exist inside Vayu for development and verification. The production native path ends at VCB.

4. Language surface

Vayu uses indentation-based blocks. The lexer emits structural INDENT and DEDENT tokens. Comments start with #.

example.vyu
def greet(name: str) -> None:
    print("Hello, " + name)

greet("Vayu")

5. Compiler pipeline

The bootstrap and reference compiler is implemented in C++ under compiler/. The driver entry point is vayuc.

Native integration

NativeCompiler writes a temporary .vcbir file and invokes vcb build. The VAYU_VCB environment variable can override the path to the VCB executable.

6. VCB backend

VCB is a standalone C++20 native compiler backend. It does not parse .vyu source. It parses VCBIR, generates x86-64 machine code, embeds required runtime helpers, and writes PE or ELF images directly.

Version
0.3.5
Phase
27 Part 3
Language
C++20, CMake 3.20+
Targets
--target pe, --target elf
IR
Typed SSA values, basic blocks, phi, branches, calls, memory ops

7. Runtime model

Runtime helpers are embedded into the native image only when referenced. A dependency scan walks the module and closes over transitive runtime requirements.

Current VCB runtime areas

  • Process exit; character, line, space, bool, integer, and float printing
  • Windows runtime imports and native helpers
  • Linux syscall output and brk-based bump allocation
  • Lists: create, push, get, set, length, print
  • Maps: create, put, get, has, length, print
  • Strings: length, equality, prefix and suffix checks, contains, find, upper, lower
  • Atomic PE and ELF writes with structural header inspection
