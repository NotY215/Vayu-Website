Vayu / Documentation / Overview

Overview

Vayu is a general-purpose programming language that combines Python-style indentation-based syntax with static typing, native compilation and low-level control.

What Vayu is

Vayu is an independent programming-language project. It is designed around a combination of:

  • Python-inspired readable syntax
  • Static typing and type inference
  • Compiled / native execution
  • Low-level memory and native interoperability
  • Object-oriented and functional programming
  • C interoperability (via extern "C")
  • Python / CPython interoperability (via the py module)
  • Self-hosting — actively being bootstrapped
  • A dedicated native compiler backend through VCB

Official source format

Vayu source files use the .vyu extension.

def greet(name: str) -> None:
    print("Hello, " + name)

greet("Vayu")

Design philosophy

Vayu aims to be one unified language spanning simple scripts, applications, AI/ML, games, and native systems software — so developers do not have to switch languages across those domains.

Simplicity
Readable by default. Python-inspired syntax keeps programs compact.
Performance
Native compilation. Recursive fib within ~2× of g++ -O2.
Control
Static types, pointers, ownership and unsafe blocks when you need them.
Interoperability
C FFI and a CPython bridge bring existing ecosystems into Vayu.
Portability
One language across scripts, applications, AI/ML, games and systems.
One ecosystem
Package manager nva, project files nova.toml / nova.lock, standard library, and toolchain.

Getting started

Install the compiler, write your first program, and run it on any of the three backends.

Installation

Vayu ships as a single C++ compiler driver called vayuc. Build instructions are maintained in the repository's build.md.

# Clone the repository
git clone https://github.com/NotY215/Vayu.git
cd Vayu

# Build vayuc (see build.md for the exact CMake invocation)
# The compiler is C++20 and has no third-party dependencies beyond
# a C++ toolchain, CMake, and (for native output) QBE + GCC.

Hello, world

Create a file called hello.vyu:

print("Hello, Vayu!")

Running programs

Vayu has three execution paths:

# Tree-walking interpreter — fastest start-up
vayuc hello.vyu --run

# Bytecode VM — balanced speed
vayuc hello.vyu --vm

# Native compiler — produces an executable
vayuc hello.vyu --native

Inspect the pipeline

The compiler can dump intermediate stages. This is useful for debugging the front-end or learning how Vayu translates your code:

vayuc hello.vyu --dump-tokens      # source → tokens
vayuc hello.vyu --dump-ast         # tokens → AST
vayuc hello.vyu --dump-bytecode    # AST → bytecode
vayuc hello.vyu --dump-ir          # AST → native IR
Reading order. If you're new to the language, this page walks through every feature in order. The syntax reference is a more compact one-page overview.

Language guide — Basics

Vayu source is indentation-based, like Python. Blocks are driven by INDENT and DEDENT tokens.

Indentation

if score >= 100:
    print("high")
else:
    print("low")

Comments

Line comments use #. There is no block-comment syntax.

# full-line comment
value = 10  # inline comment

Literals

# Integers — multiple bases
a = 10          # decimal
b = 0b1010      # binary
c = 0o755       # octal
d = 0xFF        # hexadecimal

# Floats
f1 = 3.14
f2 = 1.25e3
f3 = 2.5E-2

# Booleans and None
b1 = true       # also True
b2 = false      # also False
n  = none       # also None

# Strings and chars
s1 = "double quoted"
s2 = 'single quoted'
ch = 'a'        # single-quoted char literal

Variables

# Inferred
count = 10
ratio = 3.5
name  = "Vayu"

# Annotated
count: int   = 10
ratio: float = 3.5
name:  str   = "Vayu"

Type checking

The compiler runs a semantic/type-checking pass over explicit annotations. Assigning a string to an int is rejected at compile time.

x: int = "hello"    # compile error

The type system also includes numeric compatibility such as int → float promotion.

Generic types

Type parameters are supported on functions and classes, with optional constraints.

def identity<T>(x: T) -> T:
    return x

class Box<T>:
    value: T

def name_of<T: Named>(x: T) -> str:
    return x.name

Control flow

Conditionals, loops, range, and pattern matching.

    print("negative")
elif x == 0:

    print(item)

range()

Loop control

break
continue
pass

match / case

The parser supports literals, binders, guards, wildcards and tuple destructuring.

match n:
    case 0:
        return "zero"
    case 1:
        return "one"
    case x if x < 0:
        return "negative"
    case _:
        return "many"

match (10, 20):
    case (x, y):
        print(x + y)

Functions

Python-inspired definitions with optional type annotations.

Definition

def add(a: int, b: int) -> int:
    return a + b

Recursion

def fib(n: int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

Lambdas and closures

double = lambda x: x * 2

make_adder = lambda n: (lambda x: x + n)
add5 = make_adder(5)
print(add5(10))     # 15

Higher-order functions

Functions can be stored in variables, passed as arguments, and returned from other functions.

result = reduce(lambda a, b: a + b,
                map(lambda x: x * x,
                    filter(lambda x: x % 2 == 1, range(10))))

Generic functions

def identity<T>(x: T) -> T:
    return x

def first<T>(xs: list<T>) -> T:
    return xs[0]

Collections

Lists, maps, tuples, sets — with indexing, negative indexing, slicing and iteration.

Lists

numbers = [1, 2, 3]

print(numbers[0])       # 1

print(numbers[1:3])     # [2, 3]

Structs

Structs provide named fields with a compact construction syntax.

struct Player:
    name: str
    score: int

player = Player("NotY", 100)          # positional
player2 = Player(name="Ally", score=0) # keyword
player.score = 200                     # mutable field

The compiler supports field types, construction (positional and keyword), field access, nested structures, and visibility metadata.

Classes and inheritance

Classes support fields, constructors, methods, inheritance, overriding, super(), static members and visibility modifiers.

Basic class

class Player:
    name: str
    health: int

    def __init__(self, name: str) -> None:
        self.name = name
        self.health = 100

    def damage(self, amount: int) -> None:
        self.health = self.health - amount

    def describe(self) -> str:
        return self.name + " has " + str(self.health) + " hp"

Inheritance and super()

class Warrior(Player):
    rage: int

    def __init__(self, name: str) -> None:
        super().__init__(name)
        self.rage = 0

    def damage(self, amount: int) -> None:
        super().damage(amount)
        self.rage = self.rage + amount

Visibility and static members

class Wallet:
    public    owner:   str
    protected balance: int
    private   pin:     int

    static count: int = 0

    def __init__(self, owner: str) -> None:
        self.owner = owner
        self.balance = 0
        self.pin = 0
        Wallet.count = Wallet.count + 1

Exceptions

Vayu supports try / except / finally and raise, with multiple handlers and re-raising.

try:
    value = 10 / 0
except ZeroDivisionError as e:
    print(e.message)
except (TypeError, ValueError) as e:
    print(e.message)
except:
    print("bare except")
finally:
    print("finished")

raise ValueError("bad value")

Built-in exception types

Exception
RuntimeError
TypeError
ValueError
ZeroDivisionError
IndexError
KeyError
NameError
AttributeError

Nested exception handling, exception variables, re-raising, and raising a bare string are all supported.

Generators

Generators use yield. The VM maintains generator state across calls.

def numbers():
    yield 1
    yield 2
    yield 3

for x in numbers():
    print(x)

Manual stepping

def countdown(n: int):
    while n > 0:
        yield n
        n = n - 1

g = countdown(3)
print(next(g))   # 3
print(next(g))   # 2
print(next(g))   # 1

The VM contains generator state management, suspension / resume behavior, completion handling, and generator exception / cancellation handling. Cleanup in a finally block runs when the generator is torn down.

Modules

Modules use .vyu source files and can expose functions, constants, structs and members.

Import forms

import math_helpers
import math_helpers as mh

from math_helpers import square
from math_helpers import cube as cb

print(math_helpers.square(5))
print(mh.square(6))
print(square(7))
print(cb(3))

Namespaces

namespace Math:
    const PI = 3

    def square(x: int) -> int:
        return x * x

print(Math.PI)
print(Math.square(7))

Namespaces prefix their members internally (Math.square), which is why you can access them with dot notation.

Ownership and pointers

Ownership types and raw pointers coexist with the high-level, GC-style default.

Ownership types

unique<T>    # move-only
shared<T>    # copyable reference-counted
weak<T>      # non-owning; upgrade to shared
ptr<T>       # raw pointer
ref<T>       # resolved to T at type-check time

Move semantics

a: unique<Resource> = Resource("first")
b: unique<Resource> = a          # moves a into b

The type checker tracks moved_ scope and rejects use-after-move.

Address-of and dereference

x = 42
p = &x
print(*p)      # 42
*p = 7         # write through pointer

Pointer arithmetic and lvalue references

p + n          # arithmetic
p[i]           # indexing
p[i] = v       # indexed write

&arr[i]        # live lvalue reference
&obj.field
&m[k]

Native pointer arithmetic is direct. On the tree-walker and VM it is emulated through a backing-array model.

Raw allocation

raw: ptr<int> = malloc(sizeof(int))
free(raw)

unsafe:
    raw = malloc(8)
    *raw = 99
    free(raw)

C interoperability

Native-only. Bring C functions into Vayu with typed signatures.

extern "C" blocks

extern "C":
    def puts(s: str) -> int
    def strlen(s: str) -> int
    def llabs(x: int) -> int

print(strlen("hello"))

What native supports

  • str ↔ char* bridging
  • Function pointers (pass &topFn)
  • C callbacks
  • External-library linking via VAYU_FFI_LIBS
  • Struct-by-value FFI for small single-field cases
Interpreter and VM do not support FFI. Calling an extern "C" function from a non-native backend raises "extern C functions can only be called from the native backend".

CPython bridge

Native-only. The py module embeds CPython so Vayu can call into the Python ecosystem.

import py

py.init()
print(py.version())

m = py.import("math")
print(py.getattr(m, "pi"))
print(py.call(py.getattr(m, "sqrt"), [16]))

py.setattr(obj, "name", py.str("Alice"))
py.decref(m)

Value bridging

py.int(42)
py.str("hello")
py.bool(true)

py.from_int(handle)
py.from_str(handle)
py.from_bool(handle)

Python interop operations

py.init()          # initialize embedded CPython
py.version()       # Python version string
py.run(expr)       # run a Python expression
py.exec(code)      # execute Python code
py.eval(...)       # evaluate
py.exec_file(...)  # run a file

py.import(name)    # import a Python module
py.getattr(o, n)   # access attribute
py.setattr(o, n, v)# set attribute
py.call(fn, args)  # call a Python function
py.call_kw(...)    # keyword arguments
py.list(...)       # build a Python list
py.dict(...)       # build a Python dict
py.repr(o)         # repr()
py.type_name(o)    # type name
py.decref(o)       # decref
py.last_error()    # last Python error
Interpreter and VM cannot run the py module. Calling py.init() outside the native backend raises "py.init() requires the native backend". The bridge is a native interoperability layer, not a full CPython object-model replacement.

vayuc driver

The compiler driver is named vayuc. It runs the whole pipeline from source to executable.

Basic usage

vayuc <file.vyu> [mode] [flags]

Execution modes

--run                tree-walking interpreter
--vm                 bytecode VM
--native             native compiler (produces an executable)
--native-out <path>  native compiler with custom output path

Analysis / debugging modes

--check              type-check only
--dump-tokens        print token stream
--dump-ast           print the AST
--dump-bytecode      print generated bytecode
--dump-ir            print native IR

Additional flags

--no-check           skip type checking
--no-opt             skip optimization passes
--bench [N]          benchmark N iterations
--emit-runtime <path> emit the embedded native runtime

Examples

vayuc hello.vyu
vayuc hello.vyu --vm
vayuc hello.vyu --native
vayuc hello.vyu --check
vayuc hello.vyu --dump-tokens
vayuc hello.vyu --dump-ast
vayuc hello.vyu --dump-bytecode
vayuc hello.vyu --dump-ir
vayuc hello.vyu --bench 10
vayuc --emit-runtime runtime.c

VCB — Vayu Compiler Backend

VCB is the companion backend project — a compact C++20 backend that consumes VCB IL and emits x86-64 Intel-syntax assembly.

Repository: NotY215/VCB

Intended architecture

Vayu Source
    ↓
Vayu Frontend
    ↓
Vayu IR
    ↓
VCB
 ├─ Analysis
 ├─ Optimization
 ├─ Lowering
 └─ Native Code Generation
    ↓
Native Assembly
    ↓
Executable

VCB exists to give Vayu a dedicated native backend so frontend and language development can evolve independently of machine-code generation.

Planned backend responsibilities

  • IR analysis
  • Control-flow analysis
  • Optimization (constant folding, DCE, CSE, algebraic simplification, peephole)
  • SSA-oriented work (GVN, GCM)
  • Lowering
  • Instruction selection
  • Register allocation (linear scan)
  • Calling conventions
  • Native code generation

These are VCB development goals and should not be confused with every capability already present in the current Vayu C++ compiler.

Vayu is an early-stage independent language project with a growing compiler, runtime, VM, native compiler, FFI layer, and CPython bridge.

The source contains a substantially broader language surface than the original core compiler, including:

  • Static typing and inference
  • Functions and recursion
  • Lambdas and closures
  • Lists, maps, tuples, sets, and slicing
  • Structs and classes
  • Inheritance and overriding
  • Exceptions and modules

  • Generators and yield
