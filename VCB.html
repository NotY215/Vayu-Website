Compiler Backend

VCB — Vayu Compiler Backend.

A compact, fast, Vayu-first C++20 backend for native machine code generation. Consumes .vcbir from the Vayu compiler and emits native machine code through a short, direct pipeline.

VCBIR — the boundary

VCBIR is VCB's typed, SSA-based internal intermediate representation. It provides the boundary between the Vayu compiler and backend.

VCBIR is an internal compiler representation, not another programming language.

SSA values & blocks Phi nodes Calls & branches Loads & stores Int & FP operations Explicit conversions
VCBIR example

Typed, SSA-based, explicit.

Instructions operate on typed values with no hidden compiler state.

main.vcbirminimal example
export function i32 main() {
entry:
    %1 = add i32 5, 3
    %2 = mul i32 %1, 2
    ret i32 %2
}
Backend

The pipeline inside VCB.

Written in C++20. Inspired by compact backends such as QBE, but Vayu remains its language target.

◈

Analysis

Control-flow graph construction and data-flow information to drive every later stage.

λ

Optimization

Constant folding, dead-code elimination, common-subexpression elimination, algebraic simplification.

↘

Lowering

VCBIR → target-oriented operations, with peephole cleanups along the way.

▣

Register allocation

Linear-scan allocator assigns values to registers and stack slots.

◎

Instruction selection

Selects concrete x86-64 instructions from lowered operations.

⌁

Peephole & codegen

Final peephole optimizations, then emission of native assembly / machine code.

Why I am making VCB

A backend Vayu actually needs.

VCB exists to give Vayu its own compact native backend instead of depending on a large external compiler framework.

GoalReason
Vayu-firstBuilt around Vayu's own compiler requirements
FastKeep the compilation path short and lightweight
CompactMake the backend understandable and maintainable
NativeGenerate machine code directly from VCBIR
IndependentAvoid making Vayu depend on another backend
ExperimentalKeep backend development easy to change and test

Testing

Every stage has tests.

Tests are kept under tests/ and cover the current backend source.

tests/
├── arith.vcb # arithmetic
├── bitwise.vcb # bitwise operations
├── branch.vcb # branches
├── call.vcb # function calls
├── coalesce.vcb # register coalescing
├── compare.vcb # comparisons
├── conv.vcb # conversions
├── dense.vcb # dense control flow
├── loop.vcb # loops
├── peephole.vcb # peephole optimization
├── smoke.vcb # minimal end-to-end
└── symbolic.vcb # symbolic handling

The test suite covers arithmetic, bitwise operations, branches, calls, comparisons, conversions, loops, register coalescing, dense control flow, peephole optimization, symbolic handling, and smoke tests.
